# 0. RULES — 작업 규칙

> **모든 단계(SPEC·PLAN·TASKS·IMPLEMENT)보다 앞선다.** 무엇을 만들지 정하기 전에 지켜야 하는 것들이다.
>
> 여기 적힌 항목은 **전부 이 저장소에서 실제로 사고가 난 것**이다. 가상의 모범 사례가 아니다.
> 각 규칙에는 "무슨 일이 있었는지"를 붙였다 — 근거가 없으면 다음 사람이 규칙을 무시하기 때문이다.

> ### `CLAUDE.md` 와의 관계
>
> **`CLAUDE.md` 는 세션 시작 시 자동으로 읽히고, 이 문서는 아니다.**
> 그래서 **어기면 되돌릴 수 없거나 틀린 결론을 내게 되는 항목은 `CLAUDE.md` 에 직접 옮겨 두었다** —
> 읽을지 말지가 재량이 되면 규칙이 아니기 때문이다.
>
> 이 문서는 **근거와 전체 목록**을 담당한다. `CLAUDE.md` 에 한 줄로 압축된 규칙이
> "왜 그런지" 궁금하면 여기서 해당 절을 찾는다. 규칙을 새로 추가할 때는 **여기에 근거와 함께 적고,
> 그중 치명적인 것만 `CLAUDE.md` 로 올린다.**

## 1. 조용히 실패하는 것들

**가장 위험한 오류는 에러를 내지 않는다.** 아래는 전부 "성공한 것처럼 보이는데 안 되는" 부류다.

### 1-1. Mermaid 문법 오류는 에러를 내지 않는다

GitHub은 문법이 틀린 mermaid 블록을 **그냥 안 그린다.** 빨간 줄도, 경고도 없다.

> **실제 사고** — 다이어그램 7개 중 6개가 문법 오류였는데 커밋 직전까지 아무도 몰랐다.

**규칙**: mermaid를 추가·수정하면 **파서로 검증한다.**

```powershell
# jsdom + mermaid 로 문법만 검증한다 (렌더링 아님)
# 블록 추출 시 반드시 UTF-8 로 읽는다 — §2-2 참고
```

### 1-2. 컴파일 경고는 기본으로 꺼져 있다

`build.gradle` 에 `-Xlint:deprecation -Xlint:unchecked` 를 켜 두었다. **끄지 마라.**

> **실제 사고** — "deprecated API를 쓰고 있다"고 기록된 결함(K6)이 있었는데,
> 경고를 켜 보니 **deprecation 0건**이었다. 결함 기록 자체가 틀렸다.
> 대신 아무도 몰랐던 **진짜 경고 1건**(unchecked cast)이 드러났다.

**규칙**: "쓰고 있나 아닌가"를 추측하지 말고 **컴파일러에게 묻는다.**

### 1-3. 테스트 클래스 실행 순서는 보장되지 않는다

`agent` 테이블이 `member.email` 을 FK로 참조한다. 테스트 계정이 없으면 **FK 위반**이 난다.

> **실제 사고** — `APIAgentControllerTests` 가 `MemberRepositoryTests` 보다 먼저 돌아서
> 6개가 실패했다. 그런데 실패 메시지는 `401 ERROR_ACCESS_TOKEN` 이었다 — 토큰 문제로 보였다(§1-4).

**규칙**: DB 통합 테스트 전에 `MemberRepositoryTests` 로 계정을 만든다.
테스트끼리 순서에 의존하게 만들지 말고, 필요하면 각자 준비한다.

### 1-4. 예외를 삼키면 원인이 왜곡된다

이 저장소는 같은 실수를 **두 번** 했다.

| | 무슨 일 | 결과 |
|---|---|---|
| K1 | `substring(7)` NPE를 `catch` 가 삼킴 | "헤더 없음"인지 "토큰 깨짐"인지 로그로 구분 불가 |
| K9 | `filterChain.doFilter()` 가 `try` 안에 있음 | **DB FK 위반이 `ERROR_ACCESS_TOKEN` 401로 둔갑** |

**규칙**: `catch (Exception e)` 의 범위를 **최소로** 잡는다.
특히 필터에서 **체인 호출은 `try` 밖에서** 한다. 인증 코드가 인증과 무관한 오류까지 삼키면
디버깅이 몇 배로 길어진다.

## 2. 이 환경의 함정 (Windows · PowerShell 5.1)

### 2-1. 여러 줄에 걸친 복잡한 `sed` 치환을 하지 마라

> **실제 사고** — `sed -i` 로 mermaid 라벨을 일괄 치환하다
> **README.md와 class-diagrams.md 759줄이 통째로 오염됐다.** 모든 줄 앞에 같은 문자열이 붙었다.
> **이 저장소는 git 저장소가 아니라서 되돌릴 수 없었다.** 손상 패턴이 규칙적이라 겨우 복구했다.

**규칙**:
- **여러 개의 `-e` 를 한 번에 적용하지 않는다.** 하나가 틀리면 나머지도 같이 망가진다.
- 특수문자(`|` `&` `(` `)` `<` `>` `/`)가 섞인 치환은 **`Edit` 도구로 한다.** `sed` 로 하지 않는다.
- `sed` 는 **단순하고 유일한 패턴**(예: 식별자 이름 하나)에만 쓴다.
- 치환 후에는 **줄 수와 첫 줄**을 확인한다.

### 2-2. `Get-Content` 는 기본이 ANSI다 — 한글이 깨진다

Windows PowerShell 5.1의 `Get-Content` 는 `-Encoding UTF8` 없이 읽으면 **CP949로 해석**한다.

> **실제 사고** — mermaid 블록을 추출해 검증했더니 7개 중 6개가 "문법 오류"로 나왔다.
> 실제로는 **문법이 아니라 추출 과정에서 한글이 깨진 것**이었다.
> 그걸 모르고 다이어그램을 "고쳤고", 멀쩡한 표현을 여러 개 지웠다.

**규칙**: 한글이 든 파일을 스크립트로 읽을 때는 명시한다.

```powershell
[System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)   # 읽기
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding $false))  # 쓰기 (BOM 없이)
```

**검증 결과가 이상하면 도구를 먼저 의심한다.** 특히 "거의 다 실패"할 때는 대상이 아니라 도구가 문제다.

### 2-3. Gradle 명령은 `server/` 에서 실행한다

저장소 루트가 아니다. `cd server` 를 먼저 한다.

### 2-4. `bootRun` 전에 포트를 확인한다

> **실제 사고** — 8080이 이미 사용 중이라 `bootRun` 이 즉시 종료됐는데,
> **`BUILD SUCCESSFUL` 이 찍혔다.** 로그를 안 봤으면 서버가 뜬 줄 알았을 것이다.

**규칙**: 서버가 이미 떠 있는지 먼저 확인하고, `bootRun` 후에는 **실제 요청으로** 기동을 확인한다.

## 3. 검증 규칙

### 3-1. "통과했다"와 "안 바꿨다"는 다르다

> **실제 사고** — T1의 검증 조건은 **"`JWTUtilTests` 를 고치지 않은 채로 통과"** 였다.
> 통과한 것만 확인하고 "무변경 통과"라고 보고했는데, 실제로는 에이전트가 메서드 이름을 바꿔놨다.
> 다행히 단언은 그대로여서 결론은 유지됐지만, **단언을 고쳤다면 회귀가 숨었을 것이다.**

**규칙**: "기존 테스트를 안 고치고 통과"가 조건이면 **둘 다 확인한다.**
바꾸지 말라고 한 파일을 바꿨으면, 결과와 무관하게 **그 사실을 보고한다.**

### 3-2. 안 돌린 것을 통과했다고 쓰지 않는다

DB가 없어 `@SpringBootTest` 를 못 돌렸으면 **그 사실을 그대로 적는다.**
실패는 **출력 원문 그대로** 붙인다. 요약하지 않는다.

### 3-3. 파일이 존재하는 것과 동작하는 것은 다르다

> **실제 사고** — 파일 목록만 보고 "T1~T6, T8~T10 완료"라고 판단했는데,
> 실제로 테스트를 돌리기 전까지는 통과 여부를 몰랐다.

**규칙**: 진행 상황을 파일 존재로 판단하지 않는다. **검증 명령을 실제로 돌린다.**

### 3-4. 회귀는 새 기능보다 먼저 확인한다

새 기능이 동작하는 것보다 **기존 것이 안 깨진 것**이 우선이다.

이 프로젝트의 최우선 회귀 관문은 `docs/3-TEST.md` §6의 **21번** —
일반 사용자 토큰(`act` 없음)으로 `/api/sample/user`·`/api/sample/list` 가 **200**인가.
`SampleController` 에 `@PreAuthorize` 가 붙은 이후로, 여기가 깨지면 F1~F8이 통째로 회귀한다.

## 4. 판단 규칙

### 4-1. 기록된 것도 틀릴 수 있다 — 근거로 확인한다

> **실제 사고** — K6("deprecated API 사용")은 **결함이 아니었다.**
> `CLAUDE.md` 규칙 6은 오히려 그 API를 **쓰라고** 하고 있었다. 문서끼리 모순돼 있었다.

**규칙**: 문서와 코드가 어긋나면 **코드와 도구가 사실이다.**
결함 기록을 지우지 말고 **"정정됨"으로 근거와 함께 남긴다** — 안 그러면 다음 사람이 같은 판단을 다시 한다.

### 4-2. 관행을 따르면 되는 선택으로 멈추지 않는다

> **실제 사고** — 구현 에이전트가 "테스트 메서드 이름을 한글로 할까요 영문으로 할까요"를 묻느라
> **두 번 멈췄다.** 기존 코드를 보면 답이 나오는 문제였고, 그 사이 작업이 진행되지 않았다.

**규칙**: 기존 코드의 관행으로 답이 나오는 것은 **스스로 정하고 진행**한다.
멈춰야 하는 조건은 **미리 명시된 것만**이다 — 계약 변경, 승인 항목, 지정된 검증 관문 실패.

### 4-3. 멈춰야 하는 조건은 착수 전에 정한다

작업을 시작하기 전에 **"어디서 멈출 것인가"** 를 목록으로 만든다.
그 목록에 없으면 멈추지 않고, 있으면 반드시 멈춘다.

## 5. 되돌릴 수 없는 것

**이 문서를 쓴 시점에 이 저장소는 git 저장소가 아니었다.** 실수하면 복구 수단이 없다.
파괴적 편집 전에 **git 저장소인지 먼저 확인한다** — 아니라면 되돌릴 방법이 전혀 없다는 뜻이다.

| 대상 | 지우면 벌어지는 일 |
|---|---|
| `server/keys/` | RS256 키쌍이 **새로 생성**되고, 그 전에 발급된 **모든 토큰이 무효화**된다 |
| DB `agent` 테이블 | 등록된 에이전트가 사라져 기존 위임 토큰이 전부 `ERROR_AGENT_INACTIVE` |
| `application.properties` | `.gitignore` 대상이라 사본이 없다. `.example` 에서 다시 채워야 한다 |

**규칙**: 파일을 덮어쓰거나 지우기 전에 **대상을 먼저 읽는다.**
`server/keys/` 는 영속 스토리지에 보존한다.

## 6. 승인이 필요한 것

`CLAUDE.md` 의 절대 규칙과 같다. 여기서는 **왜** 승인이 필요한지를 적는다.

| 항목 | 이유 |
|---|---|
| 신규 gradle 의존성 | 이 프로젝트는 **의존성을 늘리지 않고** F9~F13을 구현했다. 늘리기 전에 정말 필요한지 확인한다 |
| jjwt 버전 변경 | 0.11.5 → 0.12.x 는 API가 바뀐다. `setClaims`·`parserBuilder` 가 전부 deprecated된다 |
| DB 스키마 변경 | 되돌리기 어렵고, 이미 저장된 데이터에 영향이 간다 |
| 에러 문자열 변경 | **프론트가 이 문자열로 분기한다.** 바꾸면 화면이 조용히 깨진다 (추가는 자유) |
| 응답 JSON 필드명 | 위와 같다 |
| `docs/1-SPEC.md` 의 기능 명세 변경 | 코드보다 문서가 먼저다. 명세를 고치지 않고 동작을 바꾸면 둘이 어긋난다 |

## 요약 — 한 줄씩

1. **조용히 실패하는 것을 의심한다** — mermaid · 컴파일 경고 · 테스트 순서 · 삼켜진 예외
2. **여러 줄 `sed` 치환 금지** — `Edit` 도구를 쓴다. git이 없어 되돌릴 수 없다
3. **한글 파일은 UTF-8을 명시**해서 읽고 쓴다. 검증이 대량 실패하면 도구를 먼저 의심한다
4. **"통과"와 "무변경"은 다르다.** 안 돌린 것을 통과했다고 쓰지 않는다
5. **문서보다 코드와 도구가 사실이다.** 틀린 기록은 지우지 말고 정정으로 남긴다
6. **관행으로 답이 나오면 멈추지 않는다.** 멈출 조건은 착수 전에 정한다
7. **회귀가 새 기능보다 우선이다** — 특히 §6 체크리스트 21번
