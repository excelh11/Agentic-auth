# agent-example — 실제로 위임 토큰을 쓰는 에이전트

> 저장소 이름이 `agentic-auth` 인데 정작 **AI 에이전트가 하나도 없었다.**
> 프론트 화면(`front/`)은 사람이 버튼을 눌러 **위임 메커니즘**을 확인하는 곳이다.
> 여기서는 역할을 둘로 나눠 — **[사용자]** 와 **[에이전트]** — 위임 경계를 눈에 보이게 한다.

**핵심은 이것이다.**

> 에이전트는 **사용자 비밀번호도, 사용자 토큰도 모른다.**
> 위임 토큰 하나만 받아서 그 안에 적힌 범위(`scope`) 안에서만 움직인다.

---

## 실행

백엔드가 떠 있어야 한다. 의존성은 없다 — Node 18+ 의 내장 `fetch` 만 쓴다.

```bash
# 백엔드 (다른 터미널)
cd server
./gradlew.bat bootRun

# 에이전트
cd agent-example
node agent.mjs
```

옵션:

```bash
node agent.mjs --api http://localhost:8080 --user user1@aaa.com --pw 1111
```

기대와 다른 결과가 하나라도 나오면 **종료 코드 1** 로 끝난다. CI에 그대로 걸 수 있다.

## 무엇을 보여주나

| 단계 | 누가 | 무슨 일 | SPEC |
|---|---|---|---|
| 1 | 사용자 | 로그인 — **이 토큰은 에이전트에게 넘기지 않는다** | F1 |
| 2 | 사용자 | 에이전트 등록 (`일정 봇`) — **이름은 필수** | F9-5 |
| 3 | 사용자 | `sample:read` **만** 위임. 자기는 `sample:list` 도 되지만 안 준다 | F9, F10 |
| 3 | 에이전트 | 받은 토큰을 열어 `sub` · `act` · `scope` · `aud` 를 확인 | F9-1 |
| 4 | 에이전트 | scope 안 호출 → **200** / scope 밖 호출 → **403 `ERROR_SCOPE`** | F10-1 |
| 4 | 사용자 | **같은 API를 사용자가 부르면 200** — scope 는 위임에만 걸린다 | F10 |
| 5 | 에이전트 | 스스로에게 재위임 시도 → 거부 | F9 |
| 5 | 사용자 | 자기에게 없는 `sample:admin` 위임 시도 → 거부 | F10-2 |
| 6 | 사용자 | 에이전트 회수 | F9-3 |
| 6 | 에이전트 | 아까 되던 호출이 **만료 전인데도** 막힘 → `ERROR_AGENT_INACTIVE` | F9-3 |
| 6 | 에이전트 | `refresh` 로 부활 시도 → 막힘 | F9-3, F5 |
| 6 | 사용자 | **본인 토큰은 그대로 200** | F9-4 |

**4단계와 6단계 마지막 줄이 이 프로젝트의 요점이다.**

- 같은 API인데 **에이전트는 막히고 사용자는 통과**한다 → 위임이 권한을 좁혔다는 증거
- 에이전트만 끊었는데 **사용자는 로그아웃되지 않았다** → 개별 회수가 실제로 동작한다는 증거

## 감사 로그

실행 후 `server/logs/audit.log` 를 보면 **누가 시켰고 무엇이 실행했는지**가 짝으로 남아 있다.

```
delegation-call | delegator=user1@aaa.com | actor=일정 봇 (agent-151b775d-…) | api=/api/sample/user
delegation-call | delegator=user1@aaa.com | actor=일정 봇 (agent-151b775d-…) | api=/api/sample/list
```

`actor` 에 **이름이 함께** 남는 이유 — UUID만 있으면 로그를 나중에 봐도
그게 일정 봇인지 결제 봇인지 알 수 없어서 F13의 목적("행위자 구분 불가"의 해소)이 달성되지 않는다.
